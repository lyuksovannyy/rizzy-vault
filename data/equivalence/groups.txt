# Human-editable source for the global equivalence list (ADR 0038 §1, §4): the "default site
# groups" of ADR 0080, on for every account unless the account turns a group off.
#
# NOT TOML, despite the filename ADR 0038 §1 suggests ("data/equivalence/groups.toml"): no
# TOML (or other structured-text) crate is in [workspace.dependencies], and adding one is out
# of scope (CLAUDE.md "Dependencies"). ADR 0038 §1's own fallback applies instead: "a minimal
# hand-written line format documented in the file." This is that format, kept deliberately
# small (ADR 0080 §4 keeps it).
#
# FORMAT. One group per line:
#
#   group_id (32 hex characters, 16 bytes) | third_party_hostable (0 or 1) | domain,domain,...
#
# - group_id: random, generated with an OS CSPRNG (e.g. `head -c 16 /dev/urandom | od -An
#   -tx1 | tr -d ' \n'`, or `python3 -c "import secrets; print(secrets.token_hex(16))"`),
#   assigned once and never reused or reassigned (ADR 0038 §1). Changing a group's domains or
#   its flag on an existing line never changes its id. Never derive an id from an upstream
#   `type` number (ADR 0080 §2).
# - third_party_hostable: 1 only for a domain the Public Suffix List already splits by
#   registrant (ADR 0037 §3; ADR 0038 §1, §4 point 3); 0 for everything else. No group below
#   needs it.
# - domains: two to 64, comma-separated (surrounding whitespace is trimmed), each a registrable
#   domain. `cargo xtask equivalence-list` normalises each to its IDNA A-label form and rejects
#   the line, naming the member and the rule, if a domain does not normalise, is an IP literal,
#   is not its own registrable domain (a bare public suffix such as co.uk, or a subdomain such
#   as mail.example.com; ADR 0044), there are fewer than two domains, or two domains normalise
#   to the same value.
# - Across lines (ADR 0080 §2): no group id on two lines, and NO DOMAIN IN TWO GROUPS. Overlap
#   would make "turn this group off" misleading, because the other group would still match.
# - Blank lines and lines starting with `#` are ignored.
# - Line order does not matter: `cargo xtask equivalence-list` sorts groups by id itself.
#   Append a new group anywhere; do not renumber or reorder existing lines.
# - `cargo test -p xtask` parses this committed file, so a Public Suffix List bump that turns a
#   member into a suffix fails the pull request that makes it (ADR 0044, ADR 0080 §8).
#
# REVIEW RULES (ADR 0038 §4, restated; ADR 0080 §3 adds no waiver for the seed batch):
#   1. Proof of common ownership for every entry (shared WHOIS registrant/organisation, or a
#      cross-referencing public statement on both domains). "Looks plausible" is not proof.
#   2. Two-maintainer review once a second maintainer exists; until then, the sole maintainer's
#      review, with the evidence recorded. When a second maintainer joins, the seed batch below
#      is the first thing they review, retroactively, group by group (ADR 0080 §3).
#   3. No domain a third party can host content on, unless flagged `third_party_hostable = 1`.
#   4. ccTLD variants proven per variant, not assumed from the base brand.
#   5. Scheduled re-verification at least once per release cycle; a lapsed domain is removed.
#      At each re-check, diff the shipped groups against bitwarden/server's current
#      StaticStore.cs: an upstream removal triggers re-verification of that entry before the
#      next release; an upstream addition is only a candidate for a normal proposal (ADR 0080 §3).
#   6. Small list, high bar: well-known multi-domain brands with clear public evidence, not a
#      crowd-sourced long tail.
# The evidence for every member lives in data/equivalence/EVIDENCE.md (ADR 0080 §3), one section
# per group; a member with no evidence there is dropped before signing, not waived.
#
# PROVENANCE OF THE SEED (ADR 0080 §2, §4). The groups below are derived from:
#   Vaultwarden src/static/global_domains.json
#     https://github.com/dani-garcia/vaultwarden/blob/b71cb7a832080d9fdfdd97bcccf065307cf73236/src/static/global_domains.json
#     at Vaultwarden main = b71cb7a832080d9fdfdd97bcccf065307cf73236 (file last changed in
#     dde63e209e00e4e1a02d8e43175976386a31c53b), SHA-256
#     3f2c8a39c8c1a8dd9a8c9f4c6b14201afd7113d4fea2b22a27e1847e95e7933a, 15,910 bytes.
#   which is generated from bitwarden/server src/Core/Utilities/StaticStore.cs and
#   src/Core/Enums/GlobalEquivalentDomainsType.cs, group for group identical to bitwarden/server
#   41ae9acb7b92fc8eef0b73c6cfa6eb2106a326f2.
#   The subset taken is the 22 groups bitwarden/server still maintains after PR #8404
#   (https://github.com/bitwarden/server/pull/8404, e1f32b96a33f0f5d63170690f0b83cce0b901d36:
#   "69 entries cut from StaticStore.GlobalDomains, 22 live"); each is member for member the
#   same `type` in Vaultwarden's file. The 69 cut groups are not imported.
#   Licence: AGPL-3.0 (Vaultwarden AGPL-3.0-only; Bitwarden server's default licence), compatible
#   with this project's AGPL-3.0-only (ADR 0017). Attribution: THIRD_PARTY_NOTICES.md. No
#   Bitwarden trademark is used beyond that attribution.
#   Changes from upstream: the subset above; the members removed below (amazon.com.be, net.cn,

#   starter YouTube and Google groups; fresh random group ids (upstream `type` values and
#   `excluded` are not imported).
#
